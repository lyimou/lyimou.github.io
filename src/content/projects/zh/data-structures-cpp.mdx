## 這是什麼

一組 C++11 容器與三個較大的程式，原本是課程作業，留下來的原因是**實作本身才是重點**：

- **前綴 Trie**（`trie.hpp`，約 435 行）：支援插入、前綴查詢與刪除。
- **鍵值 BST 模板**：實作拆在標頭檔與 `.tpp` 中，並在其上疊一層 **LRU 快取**。
- **手寫 `shared_ptr` 與 `weak_ptr`**：控制塊、引用計數，以及強弱引用的區別。
- **三個作業程式**：學習夥伴配對、以列表／群組模型為基礎的媒體推薦引擎，以及建立於 Trie 之上的學生記錄系統。

## 值得說明的部分

**把模板拆在 `.h` 與 `.tpp`。** 模板的定義必須在實例化的地方可見，所以實作不能單獨放在另一個編譯單元。把這個配置與對應的 include 順序弄對，才讓 BST 能被多處使用。

**自己寫一次 `shared_ptr`，會改變你對所有權的想法。** 實作需要一個引用計數的控制塊，而 `weak_ptr` 存在的意義是**打斷循環引用**——兩個物件互相持有強引用時誰也釋放不掉。讀到「循環引用」跟親眼看著自己的洩漏在把一條邊改成弱引用後消失，是完全不同的兩件事。

**Trie 是一種取捨，不是升級。** 相較於雜湊表，Trie 更耗記憶體、精確查詢也更慢，但它能在不掃描全部鍵的情況下回答「所有以這幾個字開頭的項目」。自己寫一遍，這個取捨才從課本名詞變成具體判斷。

**LRU 快取本質上是一組配對。** 快取需要 O(1) 的成員查詢與 O(1) 的淘汰，這代表需要一個映射**加上**一個有序結構，而且每次操作都要讓兩者保持一致。幾乎所有 bug 都出在這個「一致」上。

## 我學到什麼

- **RAII 是 C++ 的全部。** 所有權必須寫進型別裡，而不是寫在註解裡，否則第一個提前 return 就會洩漏。
- **模板住在標頭檔裡**，而標頭與 `.tpp` 之間多一個 `#include` 會造成只有在實例化時才浮現的 redefinition 錯誤——編譯器指向的位置往往毫無幫助。
- **除錯記憶體是另一種技能**，跟除錯邏輯不同。sanitizer 找到的問題，用 print 永遠找不到。
- **精確符合規格**（格式、順序、邊界情況）本身就是一門功夫，與「演算法寫對」是兩回事。
